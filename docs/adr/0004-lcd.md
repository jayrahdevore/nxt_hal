# ADR 0004: LCD (UC1601 over SPI)

Status: implemented and **confirmed on hardware**: the `nxt-lcd` app
displays Ferris correctly with the settings below (contrast 92, `0xC4` map
control).

## Source

Ported from the vendored NxOS driver, `nxos/base/drivers/_lcd.c`. SPI
register offsets were checked against NxOS's `at91sam7s256.h` (`AT91S_SPI`,
base `0xFFFE0000`, peripheral ID 5).

## Wiring (all PIOA)

| Pin  | Role |
|------|------|
| PA14 | SPCK, peripheral A (to the UC1601 clock) |
| PA13 | MOSI, peripheral A (to the UC1601 data in) |
| PA12 | MISO, repurposed as the **command/data** line, a plain GPIO output (low = command, high = data) |
| PA10 | NPCS2, used as the chip select, a plain GPIO output (low = selected) |

MISO carries command/data, so the panel is **write-only**: nothing can be
read back from the controller.

## SPI settings

Master mode, 8 bits, CPOL=1, NCPHA=0, SCBR=0x18 (48 MHz / 24 = 2 MHz), on
CSR0. Chip select is driven by hand: NxOS notes that letting the SPI
controller drive NPCS2 fails. Polled, no PDC. Before flipping PA12 the
shifter must be empty (`SR.TXEMPTY`), otherwise the last byte of the
previous mode is classified wrongly.

## Init sequence

Wait 20 ms, send RESET (0xE2), wait 20 ms, then as commands:
`0x23` (multiplex 1/65), `0xEB` (bias 1/9), `0x81 0x5C` (potentiometer 92,
about 9 V V(LCD)), `0x89` (RAM address control: auto-wrap, row-major), `0xC4`
(Y mirror, the panel is mounted upside down), `0x00 0x10 0xB0` (cursor at
0,0), `0xAF` (display on). The waits service the AVR link via a closure.

## Framebuffer

100x64, 8 pages x 100 columns. Byte `page * 100 + x` holds the 8 vertical
pixels of column `x`, bit 0 = top, 1 = dark. A flush sends, per page,
`0x00 0x10 0xB0|page` as commands and then 100 data bytes.

## Ferris image

`firmware/nxt-lcd/assets/rustacean-flat-happy.svg` (from rustacean.net) is
rasterised at 96x64, letterboxed to 100x64 and hard-thresholded at 55% by
`tools/img2lcd/convert.sh`. `tools/img2lcd/img2lcd.rs` packs the PBM into
the layout above and writes `firmware/nxt-lcd/src/ferris.rs`, which is
committed so firmware builds need no image tooling. Dithering was tried and
turned the orange body into noise.

The same script also builds the bootloader's splash, `WRENCH`, from the
hand-drawn `firmware/nxt-boot/assets/wrench.svg` into
`firmware/nxt-boot/src/wrench.rs`.

Packer tests: `rustc --edition 2021 --test tools/img2lcd/img2lcd.rs -o /tmp/t && /tmp/t`.

## Notes

- Contrast (potentiometer 92) may still need adjusting on other panels.
- If an image ever shows mirrored or upside down, revisit the `0xC4`
  map-control byte. If it is offset, revisit the column address commands.
- The bootloader reuses this driver for its wrench splash screen; see
  ADR 0003. The splash path itself is not yet verified on hardware.
